# 地点证据与联网检索

用户补充文字或确认采用 OCR 后，系统按需查证：

1. 本地城市名、中文名，以及导入的城市别名、POI、道路索引。
2. 高置信且唯一的本地命中参与地点匹配加分；不唯一或不足时进入联网地名检索。
3. 联网地名结果只召回目录城市候选，不直接获得地点匹配加分；结果不足或冲突时，可调用网页搜索。标题与摘要中提到的城市同样只成为候选。
4. 候选补齐真实 StreetCLIP 图像分后进入同一个打分器；网页排名、城市人口和重复网页都不能代替图像分。

所有联网结果都不直接给城市加地点匹配分，不写城市事实，也不用外部坐标。国家、城市身份和最终地图坐标仍来自项目目录。同名冲突保留并请求澄清，不把搜索第一条当答案。

## 来源与解释

候选保留原线索、匹配类别、检索来源和时间。网页来源提供标题、摘要及可点击链接；OCR 与用户补充分别标注文字来源。模型观察单独标为模型信号，不当作外部核验。

LLM 负责提取原话和解释这些证据，不能增加来源没有支持的地点事实，也不能改分或自行确认城市。高置信路径继续跳过不必要的语言生成。

## 开启网页搜索

原有 `M_PHOTO_GEOCODER_*` 配置继续有效。额外网页搜索默认 `M_PHOTO_WEB_SEARCH_PROVIDER=none`，需要选择服务：

- Tavily：设置 `M_PHOTO_WEB_SEARCH_PROVIDER=tavily` 和 `M_PHOTO_WEB_SEARCH_API_KEY`；接口默认 `https://api.tavily.com/search`。
- SearXNG：设置 `M_PHOTO_WEB_SEARCH_PROVIDER=searxng` 和 `M_PHOTO_WEB_SEARCH_BASE_URL`，该实例须允许 JSON 搜索结果。

配置示例见 `.env.example`。修改运行配置后重新创建后端容器。服务不可用、超时或没有结果时，保留原线索和已有歧义，明确说明原因；不把服务故障解释为没有这个地点。

只发送有界的地点检索词和国家范围，不发送照片、聊天记录、图像路径或坐标。未经用户确认采用的 OCR 不自动发送到额外网页服务。请求有缓存、超时和失败冷却；批量评测不自动启用联网。

## 本地道路和 POI

项目已有城市目录和中文城市名，没有随项目附带完整道路/POI 数据。新增索引是数据入口，不能据此宣称已覆盖所有道路和店铺。

导入记录须有真实目录 `city_id`、所属国家范围和可追溯来源。同名记录全部保留；缺少来源、身份不符或置信度不足的记录不能获得高置信匹配加分。不会在代码里写死“玉林路就是成都”。

索引 JSON 使用 `{"entries": [...]}`；每项包含 `name`、`kind`（`city_alias` / `poi` / `road`）、`city_id`、`source_iso`、`confidence` 和 `sources`。来源至少保留 `label`；道路/POI 还须有可追溯的 `url`。只有配置置信度不低于 0.9 且通过目录身份校验的项才可参与高置信匹配；该配置值不是定位概率。

默认路径是 `data/place-evidence.json`，可通过 `M_PHOTO_LOCAL_PLACE_INDEX` 指定容器内路径。索引未提供时为空；已有城市目录和中文名继续有效。

本次不运行回归测试，按用户要求留给手测。联网召回是否改善准确率仍需后续对照评测。
